# Reviewing the justfile, CI, versions and release

The law is `CLAUDE.md` → *Task runner*, *Distribution*, *Plugin* and *Docs site*;
`DECISIONS.md` has the reasons (*Version centralization*, *Breadth-SDK publishing*, *CLI npm
launcher*).

## Never

- A second justfile, or one anywhere but the repo root.
- A CI job that runs a raw tool. Each job calls one named recipe; the main job calls `just ci`.
- A README, `CONTRIBUTING.md` or workflow that shows the underlying command instead of the
  recipe.
- A manual step between green CI and a release. If release confidence depends on it, it is an
  automated check.
- A stored npm, PyPI, NuGet or crates.io token. Those channels publish by OIDC trusted
  publishing. Maven Central is the one channel with stored secrets.
- A hand edit to `.github/workflows/release.yml`: it is generated by dist and drift-checked by
  `just dist-check`.
- A hand edit to a version. `just set-version` is the single writer.

## Check

- **Recipes are thin wrappers,** and the default recipe lists them.
- **Version pins agree:** `just version-check` is the single drift guard and round-trips the
  writer. It covers every manifest, the plugin's `plugin.json` and the `npx` pin in `.mcp.json`.
- **Release configuration:** `just dist-check`, `just publish-check`, `just plugin-check`.
- **Crates are publishable:** a spec-reading build script reads a crate-local `openapi.json`,
  kept in sync by per-crate tests, because a published package has no repo root.
- **Tool pins** (cargo-dist, the openapi-generator wrapper and jar, the nightly rustfmt date)
  each live in one place.
- **A new publish channel or workflow** is tag-driven, and its one-time setup is written down
  where `CLAUDE.md` → *Distribution* lists the others.
- **The docs site:** `just docs-check` covers drift, the build and the analytics-tag guard.
  The API reference is built from the overlaid spec; docs-only spec transforms live in
  `codegen/docs-spec.jq`, not in the shared overlay.

## Gotchas this repo has met

- **A workflow that cannot be edited.** dist's own npm job is token-only and `release.yml` is
  generated, so the CLI's npm launcher publishes from a separate workflow chained on
  `workflow_run`.
- **The default `GITHUB_TOKEN` cannot trigger the tag workflows.** The cut-release action
  pushes its tag with a separate token for that reason.
- **cargo-dist 0.32's Homebrew template has no completion or man-page wiring.** The archives
  include them; automatic Homebrew wiring waits on a dist upgrade.
- **cargo-dist 0.32's npm installer does not checksum the binary it downloads.** That risk is
  known and accepted; the shell and Homebrew installers do verify.
